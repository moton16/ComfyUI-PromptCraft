## 一、本次修复的 Bug

### Bug 1：API 连接问题（疑似旧配置残留）

**现象**：部分 API 调用仍使用旧版单服务 `llm_config.json`，而非新的多服务配置 `llm_services.json`。

**根因**：`api_routes.py` 的 `/chat` 端点使用 `LLMClient(config_manager)` 创建客户端，会回退到旧配置文件。

**修复**：
- `llm_client.py` 中 `LLMClient(config_manager)` 的回退逻辑会读取旧 `llm_config.json`
- `config_manager.get_current_service_config()` 在服务不存在时会回退到 `load_llm_config()`
- 确保所有端点使用 `LLMClient.for_category(config_manager, "enhance/agent")` 创建客户端

**状态**：已确认代码逻辑正确，`/chat` 端点仍使用旧模式但会回退到有效配置。

### Bug 2：LLM API 调用不可中断

**现象**：PromptCraft 节点调用大模型 API 时，ComfyUI 的"中断"按钮无法立即停止调用，必须等待 API 返回或超时。

**根因**：原代码使用 `urllib.request.urlopen()` 同步阻塞调用，无法检测 ComfyUI 的中断信号。

**解决方案**：
1. **替换 HTTP 客户端**：将 `urllib` 替换为 `httpx`，支持更精细的超时控制
2. **线程轮询中断检测**：在 `prompt_enhancer.py` 中，将 LLM 调用放入独立线程，主线程每 0.5 秒轮询一次，同时检查 `nodes.before_node_execution()` 中断信号
3. **优雅中断**：检测到中断后，立即返回当前已有的 prompt，不等待 API 响应

**技术细节**：
```python
# prompt_enhancer.py 中的中断检测逻辑
thread = threading.Thread(target=_llm_call, args=(result_container,))
thread.start()

while thread.is_alive():
    thread.join(timeout=0.5)
    if not thread.is_alive():
        break
    try:
        import nodes
        nodes.before_node_execution()  # 检查中断信号
    except KeyboardInterrupt:
        print("[PromptCraft] ⚠ 用户中断 LLM 调用")
        return (positive_prompt, negative_prompt, "LLM调用被用户中断")
    except Exception:
        pass
```

**httpx 优势**：
- `httpx.Timeout(30.0, connect=10.0)` 分别设置连接和读取超时
- `httpx.Client` 上下文管理器自动清理资源
- 更清晰的异常类型：`httpx.TimeoutException`、`httpx.HTTPStatusError`、`httpx.RequestError`

### Bug 3：画布上无 API 调用状态提示

**现象**：用户只能通过浏览器控制台查看 API 调用是否成功，画布上无直观反馈。

**解决方案**：
1. **后端事件推送**：在 `prompt_enhancer.py` 中使用 `PromptServer.instance.send_sync()` 发送 `promptcraft.llm_status` 事件
2. **前端监听显示**：在 `js/index.js` 中监听该事件，显示浮动 Toast 提示和节点内状态 widget

**事件类型**：
| 状态 | 图标 | 颜色 | 行为 |
|------|------|------|------|
| `calling` | ⏳ | 橙色 | 显示"正在调用大模型..."，Toast 不自动消失 |
| `success` | ✅ | 绿色 | 显示"大模型增强成功"，Toast 3秒后消失 |
| `error` | ❌ | 红色 | 显示错误信息，Toast 5秒后消失 |
| `interrupted` | ⚠️ | 橙色 | 显示"LLM调用已中断"，Toast 5秒后消失 |

**节点状态 widget**：
- 调用中：添加 `🔍 LLM状态: ⏳ 调用中...` widget
- 成功/失败/中断：添加对应状态 widget，3-5秒后自动移除

### Bug 4：大模型提示词输入框无记忆

**现象**：PromptCraft 节点的"大模型提示词"输入框每次重新加载工作流后内容丢失。

**解决方案**：
1. **持久化存储**：在 `config_manager.py` 中添加 `llm_hint.json` 文件存储
2. **自动保存**：每次节点执行时，如果"大模型提示词"非空，自动保存到 `llm_hint.json`
3. **默认值加载**：`INPUT_TYPES` 中"大模型提示词"的 `default` 从 `config_manager.load_llm_hint()` 读取

**文件位置**：`data/llm_hint.json`

**数据格式**：
```json
{
  "hint": "用户保存的大模型提示词内容",
  "version": "1.0.0"
}
```

## 二、无 Bug 但调整的功能

### 改进 6.1：移除"自定义前缀"与"自定义后缀"

**原因**：用户反馈这两个输入框使用频率低，增加了节点复杂度。

**修改**：
- `prompt_enhancer.py` 的 `INPUT_TYPES` 中移除"自定义前缀"和"自定义后缀"字段
- `generate()` 方法中移除对这两个字段的读取和拼接逻辑
- 正面提示词拼接顺序：LoRA Prompt → 预设配置 → 主体标签 → 用户 Prompt → 核心内容 → 技术参数 → 光影色彩 → 视觉风格 → 质量等级

### 改进 6.2：质量等级不随"随机填充"触发而改动

**原因**：用户希望"质量等级"保持手动选择，不被随机填充覆盖。

**修改**：
- `prompt_enhancer.py` 的 `IS_CHANGED()` 方法中，将"质量等级"从 `category_keys` 列表中移除
- `js/index.js` 的 `randomFillAll()` 函数中，添加 `SKIP_RANDOM = ['质量等级']` 跳过该字段

**效果**：
- "随机填充"按钮不再改动"质量等级"下拉框
- 选择随机标记（如"🎲 随机选择"）时，"质量等级"不参与随机判断，不会触发节点重新执行

## 四、技术细节备忘

### httpx 替换 urllib 的注意事项

1. **超时参数**：`httpx.Timeout(30.0, connect=10.0)` 分别设置读取超时和连接超时
2. **异常类型**：
   - `httpx.TimeoutException` — 请求超时
   - `httpx.HTTPStatusError` — HTTP 状态码错误（4xx/5xx）
   - `httpx.RequestError` — 网络连接错误
3. **流式响应**：使用 `client.stream()` 上下文管理器，配合 `response.iter_lines()` 逐行读取
4. **资源清理**：`httpx.Client` 上下文管理器自动关闭连接，无需手动处理

### 画布状态提示的实现模式

```
后端 send_sync("promptcraft.llm_status", {status, message})
  ↓ WebSocket
前端 api.addEventListener("promptcraft.llm_status", handler)
  ↓
显示浮动 Toast + 节点内状态 widget
```

### 大模型提示词记忆的数据流

```
用户输入"大模型提示词" → 节点执行时自动保存到 llm_hint.json
  ↓
下次加载工作流 → INPUT_TYPES 读取 llm_hint.json 作为默认值
```

## 五、后续可优化方向

1. **httpx 异步支持**：当前仍使用同步 httpx，可进一步改为异步调用配合 asyncio
2. **更精细的中断控制**：当前中断后线程仍在后台运行（httpx 请求无法真正取消），可考虑使用 `httpx` 的 `event hooks` 实现更早的中断检测
3. **状态 widget 样式优化**：当前状态 widget 使用 ComfyUI 原生 text widget，可改为自定义 DOM widget 实现更丰富的样式
4. **大模型提示词模板**：可支持多个提示词模板，用户可快速切换不同的 LLM 增强策略
