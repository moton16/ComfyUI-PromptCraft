## 一、本次修复的 UX 问题

### 问题 1：画布节点 LLM 状态弹窗干扰 UI

**现象**：启用"语言大模型接入"后，PromptEnhancer 节点上会动态添加一个"🔍 LLM状态" widget，调用结束后 3-5 秒自动移除。这个过程导致：
- 节点尺寸反复变化，画布布局抖动
- 与其他节点的连线位置偏移
- 视觉上非常突兀，影响工作流编辑体验

**根因**：`js/index.js` 中 `updateNodeLlmStatus()` 函数在节点上 `addWidget` / `splice` widget，触发 `setSize` 和 `setDirtyCanvas`，造成画布重排。

**修复方案**：
- 删除 `updateNodeLlmStatus()` 函数（约 40 行）
- 删除事件监听器中对节点 widget 的操作逻辑
- 保留浮动 Toast 通知（`showLlmStatusToast`），它不影响画布布局
- "calling" 状态的 Toast 现在也会显示（之前被 `if (status !== 'calling')` 跳过），持续到被 success/error/interrupted 替换

**效果**：LLM 状态通过右上角浮动提示显示，不干扰画布节点 UI。

## 二、代码结构优化（基于代码审计报告 P0 级别）

### 优化 1：抽取公共 LoRA 工具函数

**问题**：`model_lora_loader.py` 和 `lora_prompt_loader.py` 中 `_flatten_stack()` 和 `_load_single_lora()` 完全相同（约 60 行），任何逻辑改动需同步两处。

**方案**：新建 `lora_utils.py`，包含：
- `flatten_stack(items)` — 展平栈条目（group ref 递归展开）
- `load_single_lora(model, clip, lora_name, strength_model, strength_clip)` — 加载单个 LoRA（带缓存）
- `clear_cache()` — 清空 LoRA 文件缓存

**变更**：
- `model_lora_loader.py`：删除 `_flatten_stack`、`_load_single_lora`、`_lora_cache`，改为 import `lora_utils`
- `lora_prompt_loader.py`：同上
- 共享缓存：两个节点现在共享同一个 `_lora_cache`，避免重复加载同一 LoRA 文件

### 优化 2：提取 mtime 缓存 Mixin

**问题**：`config_manager.py`、`lora_group_manager.py`、`lora_prompt_manager.py` 各自实现了一套几乎相同的 mtime 缓存模式（检查文件修改时间 → 缓存命中/失效 → 重新加载）。

**方案**：新建 `cache_utils.py`，包含 `MtimeCacheMixin` 类：
- `_init_mtime_cache()` — 初始化缓存状态
- `_load_json_with_cache(key=None)` — 带 mtime 缓存的 JSON 加载，支持提取指定 key
- `_save_json_and_update_cache(data)` — 原子写入并更新缓存

**变更**：
- `lora_group_manager.py`：继承 `MtimeCacheMixin`，`load_groups()` 从 22 行缩减为 3 行
- `lora_prompt_manager.py`：继承 `MtimeCacheMixin`，`load_all()` 从 22 行缩减为 3 行
- `config_manager.py`：暂未改动（缓存逻辑更复杂，有模板恢复等额外步骤，不适合简单 mixin）

### 优化 3：API 路由装饰器

**问题**：`api_routes.py` 33 个路由函数中，大多数遵循 `try/except → get_result_json` 模板。

**方案**：添加 `api_handler(log_msg=None)` 装饰器：
- 统一 try/except 异常处理
- 自动构建标准响应格式
- 支持自定义日志消息
- 区分 ValueError（400）和通用异常（500）

**使用方式**：
```python
@PromptServer.instance.routes.get(f"{API_PREFIX}/xxx")
@api_handler("获取 XXX")
async def xxx(request):
    return config_manager.load_xxx()
```

**注**：装饰器已添加，现有路由暂未批量改写。后续新增路由应使用此装饰器，现有路由可逐步迁移。

### 优化 4：删除重复日志

**问题**：`api_routes.py` 中 3 行注册日志出现了两次（第 541-543 行和第 858-860 行），第一处在文件中部（还有后续路由未注册），第二处在文件末尾。

**修复**：删除第一处（中部）的 3 行重复日志。

## 五、技术细节备忘

### 共享 LoRA 缓存

`lora_utils.py` 中的 `_lora_cache` 是模块级变量，`ModelLoraGroupLoader` 和 `LoraPromptLoader` 共享同一个缓存。这意味着：
- 同一 LoRA 文件只会被 `comfy.utils.load_torch_file` 加载一次
- 两个节点在同一工作流中使用同一 LoRA 时，内存占用减半
- `clear_cache()` 会清空共享缓存，两个节点都会受影响

### MtimeCacheMixin 的 key 参数

`_load_json_with_cache(key="groups")` 会从缓存的完整 JSON 中提取指定 key。缓存存储的是完整数据（如 `{"version": "1.0.0", "groups": {...}}`），返回的是提取后的数据（如 `{...}`）。这样 save 时可以直接缓存完整结构，load 时按需提取。

### api_handler 装饰器的 ValueError 处理

装饰器将 `ValueError` 映射为 HTTP 400（客户端错误），其他异常映射为 500（服务器错误）。这与现有路由中手动区分 `except ValueError` 和 `except Exception` 的模式一致。
